🎯 设计目标

  1. 统一拦截点：在 plugin-host-rpc.ts 的 loadPlugin 中一次性设置全局拦截
  2. 覆盖所有插件：Theia 插件、VSCode 插件、Headless 插件都受保护
  3. 覆盖所有加载方式：import、require、动态 require 都能拦截
  4. 简化 init 文件：backend-init-theia.ts 和 plugin-vscode-init.ts 只负责 API 注入

🔧 实现要点

1. UnifiedModuleInterceptor (统一拦截器)

职责：

  • 管理全局 module._load 劫持（只设置一次）
  • 维护已加载插件列表（用于识别插件）
  • 创建模块代理（fs, child_process, http, net, etc.）
  • 调用权限服务进行检查

关键方法：

class UnifiedModuleInterceptor { // 一次性设置全局 hook（第一个插件加载时） static setupGlobalHook(permissionService: ModulePermissionChecker): void // 注册插件信息（每个插件加载时） static registerPlugin(plugin: Plugin): void // 识别是哪个插件在加载模块 private static identifyPlugin(parentFilename: string): Plugin | null // 判断是否需要拦截 private static shouldIntercept(moduleId: string): boolean // 创建代理模块 private static createProxy(module: any, moduleId: string, plugin: Plugin): any }

2. 修改 plugin-host-rpc.ts

loadPlugin(plugin: Plugin): any { // 🔥 第一次加载插件时，设置全局拦截 if (!UnifiedModuleInterceptor.isInitialized()) { UnifiedModuleInterceptor.setupGlobalHook(this.permissionService); } // 🔥 注册插件信息 UnifiedModuleInterceptor.registerPlugin(plugin); // ❌ 删除这些调用： // FileSystemInterceptor.interceptFsModule(plugin); // ModuleInterceptor.startInterception(plugin); // 加载插件主文件 return dynamicRequire(plugin.pluginPath); }

3. 简化 backend-init-theia.ts

function overrideInternalLoad(): void { const module = require('module'); const internalLoad = module._load; module._load = function (request: string, parent: any, isMain: {}): any { // ✅ 只处理 @theia/plugin API 注入 if (request === '@theia/plugin') { const plugin = findPlugin(parent.filename); if (plugin) { return pluginsApiImpl.get(plugin.model.id); } return defaultApi; } // ❌ 删除所有 ModuleInterceptor 相关代码 // ❌ 删除所有敏感模块拦截逻辑 // ✅ 其他模块正常加载（拦截已在 UnifiedModuleInterceptor 中统一处理） return internalLoad.apply(this, arguments); }; }

🎨 权限对话框 UI

对话框内容：

⚠️ Plugin Permission Request

Plugin: "GitHub Copilot" (v1.2.3)

Wants to perform:

  • Module: child_process.exec
  • Command: git status

⚠️ This operation can execute system commands

选项说明：

  • Deny: 拒绝本次操作，插件会收到权限错误
  • Allow Once: 允许本次操作，下次还会询问
  • Always Allow: 始终允许该插件的此类操作，不再询问

📊 权限策略存储

interface PermissionPolicy { pluginId: string; moduleId: string; decision: 'allow' | 'deny' | 'ask'; timestamp: number; }

策略存储位置：

  • 前端: ModulePermissionService 维护运行时缓存
  • 持久化: 保存到用户配置文件（如 ~/.theia/plugin-permissions.json）
